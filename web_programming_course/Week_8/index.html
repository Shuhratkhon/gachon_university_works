TRACEABLE CHANGES

Problem → fix → proof

WHAT WE FOUND

Native validation can interrupt custom feedback before the intended submit logic runs.

→
HOW IT WAS FIXED

Use novalidate and event.preventDefault(), then handle validity deliberately.

✓ Test: empty fields show the intended validation feedback.

WHAT WE FOUND

An error may not be clearly associated with the field it describes.

→
HOW IT WAS FIXED

Connect inputs and messages with aria-describedby and update aria-invalid.

✓ Test: error messages are associated with the right fields.

WHAT WE FOUND

The form needs to explain when confirmation differs from the password.

→
HOW IT WAS FIXED

Compare both values and use setCustomValidity() to set or clear the mismatch.

✓ Test: mismatched passwords block submission.

WHAT WE FOUND

After valid submission, the user needs to know the form was accepted.

→
HOW IT WAS FIXED

Show a success message in a status area with aria-live="polite".

✓ Test: success feedback is visible and announced.

FINAL PASS

Re-test after every fix.

A code change alone does not prove an improvement. Repeat the same checks and confirm that the expected behavior works.

  • ✓ Empty fields show validation feedback
  • ✓ Password mismatch blocks submission
  • ✓ Valid input displays success status
